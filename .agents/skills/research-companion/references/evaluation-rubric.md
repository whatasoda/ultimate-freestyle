# 評価基準

## 採点方法

8観点を0〜4で評価する。根拠不足は `NE` とし、0点と区別する。

- `0`：存在しない、または重大な矛盾がある
- `1`：意図はあるが曖昧で、実行・説明に使えない
- `2`：最低限成立するが、根拠・範囲・具体性が不足する
- `3`：明確な根拠があり、発表として十分に成立する
- `4`：選択理由と限界まで説明でき、研究固有の強さがある
- `NE`：現時点のファイル・記録から判断できない

制作途中では合計点を完成度と呼ばない。提出前だけ、全項目が数値評価できる場合に合計する。

## 8観点

### 1. 問いの明確さ

- 対象と知りたいことが疑問文で特定されているか
- 調査、観察、比較、制作によって答えに近づけるか
- 範囲が期間と資源に対して現実的か

### 2. 仮説と判定可能性

- 結果を見る前の予想と理由が残っているか
- 支持・反証・保留を分ける基準があるか
- 結果に合わせて仮説を書き換えていないか

### 3. 方法の妥当性と再現性

- 条件、手順、比較対象、回数が具体的か
- 問いに対して方法が対応しているか
- 安全、費用、第三者への影響が管理されているか

### 4. 記録と証拠

- 日時、条件、結果、失敗、欠測が残っているか
- 主張を写真、数値、ログ、制作物などで示せるか
- 都合のよい例だけを選んでいないか

### 5. 考察と限界

- 観察事実と解釈を区別しているか
- 仮説と違う結果や別の説明を扱っているか
- 言えることと言えないことを明示しているか

### 6. 独自性と本人性

- 本人の関心、経験、試行錯誤が中心にあるか
- 既存情報の要約だけで終わっていないか
- 失敗や判断に本人固有の発見があるか

### 7. 発表構成と明瞭さ

- きっかけから結論まで因果がつながるか
- 一枚一メッセージで、最重要の証拠が目立つか
- 20分以内で、無音でも主要内容が伝わるか

### 8. 信頼性と制作整合性

- 引用、素材、音声、キャラクターの出典・規約を確認したか
- 画面、読み上げ、BIIM補足の役割が混線していないか
- 外部URL、操作、音量、表示、クレジットを本番相当で確認したか

## 必須条件

一つでも未確認なら「提出可能」と判定しない。

- 発表時間が20分以内
- 引用元・素材元・音声クレジットが必要に応じて明記されている
- 捏造したデータ、体験、出典がない
- ゲーム映像等を使う場合に配信ガイドラインを確認している
- 外部URLを第三者が閲覧できる
- 元データと提出データを本人が保持している
- カシヲ氏本人の協力が必要な場合は事前連絡している
- 音声がなくても研究の要点が伝わる
- 本番相当の端末・ブラウザで通し確認している

## 判定の目安

全項目が数値評価でき、必須条件を満たす場合だけ使う。

- `0〜11` 種の段階：問いか方法から対話を再開する
- `12〜21` 研究進行中：証拠と考察を優先する
- `22〜27` 発表準備中：弱い観点を一つずつ補強する
- `28〜32` 提出候補：必須条件と通し練習を再確認する

合計点だけで良否を決めない。0〜1の観点、`NE`、必須条件の未確認を先に扱う。

## 評価出力

各点に、ファイル名、記録、発言、データなど確認できる根拠を添える。根拠のない称賛や減点をしない。

```markdown
### 暫定評価 YYYY-MM-DD
| 観点 | 評価 | 根拠 | 次に必要なもの |
|---|---:|---|---|
| 問いの明確さ | 3 | READMEの研究の問い | 対象期間を決める |

- 強み：根拠付きで一つ
- 最大のリスク：提出や結論を危うくするもの一つ
- 最優先の改善：次に行う具体作業一つ
- 次の質問：改善へつながる一問
```

## 自己評価と外部評価

ユーザー自身の点数も聞ける場合は、エージェント評価と並べる。差が2点以上ある観点では、どちらが正しいか決めつけず、見ている根拠の違いを一問で確認する。
