# 発表制作フロー

研究内容を変えず、画面、読み上げ、補足、デザインを一貫した発表へするためのproduction手順。

## 1. 正本を読む

- Remote MCP接続時は`get_project_outline`、`research://projects/{id}/research`、`research://projects/{id}/deck`、`research://guide/presentation-design-workflow`を読む。
- ローカル研究はREADMEとdeckを読む。
- 主張、最重要の証拠、限界、作者の好み、避けたい表現を混ぜずに取り出す。

## 2. design briefを作る

次を4行以内にする。

- 研究らしさの核
- 最も目立たせる証拠
- 色・文字・素材感の方向
- 避ける表現

不足する場合は一度に一問だけ聞く。未回答を見栄えのよい設定で埋めない。

## 3. 3方向を比較する

各案へ名前を付け、配色、font、領域・密度、見出し・画像・パネル、動き、向く証拠を示す。色だけ違う案、既存preset名だけの案、研究と関係のない流行表現は案として数えない。利用者が一案を選ぶまで保存しない。

## 4. 小粒度で適用する

- design briefと採用理由をtemplateの`design_notes`へ残す。
- 基本templateを最大8項目ずつ変更する。
- 各スライドへ表紙、章扉、本文、比較、結果、結びのroleを割り当てる。
- role差分でvisual preset、font、領域、密度、余白、配色、モチーフ、見出し、画像、パネル、動きを必要な分だけ上書きする。
- 一枚固有の文章配分はflow typography、自由構成はscene component、単純な絶対配置はcanvas blockで調整する。
- 成功応答のversionを次の`expected_version`へ渡す。競合時はresourceを再読する。

## 5. 9/10を確認する

見た目の多様性は次の5項目、AI制作は次の5項目を各1点として扱う。

### 見た目

- 配色、font、領域・密度、部品処理、動きの5軸に説明できる意図がある。
- 3方向を色以外の情報階層でも判別できる。
- 表紙、本文、結果、結びを同じ研究らしさの中で描き分けている。
- 内容量と証拠形式にflow、scene、canvasを使い分けている。
- 16:9または4:3の実rendererで見切れとコントラスト問題がない。

### AI制作

- briefと変更理由が保存されている。
- 対象resourceを読んでからfield単位で変更している。
- 提案、採用確認、適用、再読取、実表示確認を行っている。
- role差分とcomponent styleを使い分け、全量を再送していない。
- 変更、継承、残る確認事項を利用者へ返している。

9/10は合計9項目以上を満たし、研究内容の無断変更、任意コード、見切れ、コントラスト不足がない状態。満たさない場合は最も効果の高い一項目だけを次の改善にする。

## 6. 終了時に返す

- 採用した方向と研究との接続
- 基本templateで変えた軸
- roleごとの差分
- 一枚固有の構成変更
- Web UIで利用者が確認する箇所
