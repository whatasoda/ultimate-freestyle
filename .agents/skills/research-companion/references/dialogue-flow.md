# 対話フロー

必要なフェーズだけを使い、先の質問をまとめて出さない。ユーザーが十分に答えた項目は繰り返さない。

## 0. セッション開始

確認する順序：

1. 対象研究または新規候補
2. 今日終えたいこと
3. 使える時間

最初の質問例：「今日はテーマ探し、方法決め、記録整理、発表づくり、評価のどこまで進めたいですか？」

終了条件：対象と今回のゴールが一文で言える。

## 1. 種を見つける

順番に掘る：

1. 最近、妙に気になったこと・繰り返したこと
2. どこが予想外、不便、面白い、納得できないのか
3. 本人でなければ気づきにくい経験
4. 実際に触れる対象と使える時間

質問例：

- 「最近、理由は分からないけれど何度も見てしまったものはありますか？」
- 「結果が分かっていても試したくなるのはどれですか？」
- 「一週間なら、観察・制作・比較のどれが一番続けられそうですか？」

終了条件：候補が最大3個になり、本人の関心と実行可能性を説明できる。

## 2. 問いを作る

「対象」「変えるもの」「見るもの」「範囲」を一つずつ決める。

弱い問い：「○○について調べる」

強める方向：

- 条件を変えたら何が変わるか
- 一般的な説明が自分の状況でも成立するか
- どこまで、いつから、何回で変化するか
- 作り方の違いが体験へどう影響するか

終了条件：問いが疑問文で書け、観察または制作物で答えに近づける。

## 3. 仮説と判定を決める

先に予想を聞き、その理由を本人の経験と外部情報に分ける。次に、何が起きれば予想を支持・反証・保留とするかを決める。

質問例：「結果Aと結果Bの境目を、何で判断できそうですか？」

終了条件：結果を見る前の予想と、判定基準が記録されている。

## 4. 方法を設計する

一度に一要素ずつ確認する。

1. 対象と条件
2. 比較対象または基準
3. 回数と期間
4. 記録項目と記録手段
5. 失敗時の扱い
6. 安全、費用、権利、第三者への影響

可能なら最小の予備試行を先に行う。方法を複雑にするより、残せる記録を優先する。

終了条件：別の日でも同じ手順を再現でき、何を保存するか決まっている。

## 5. 実行とログを伴走する

各回で尋ねる順序：

1. 実際にしたこと
2. 観察した事実
3. 予想との差
4. 手順上の問題
5. 次回一つだけ変えること

事実と感想を別欄にする。都合の悪い結果、欠測、やり直しも残す。

終了条件：次の試行が具体的、または分析に足る記録が揃った。

## 6. 結果を読む

順番に確認する：

1. 最も明確な事実
2. 例外と失敗
3. 仮説との一致・不一致
4. 別の説明
5. 言える範囲と言えない範囲

相関だけで原因を断定しない。サンプルが少ない場合は、小さいことを欠点として隠さず研究の範囲として示す。

終了条件：主張、証拠、限界がそれぞれ一文で書ける。

## 7. 発表の物語を作る

次の骨格を基本にする。

1. きっかけ
2. 問いと予想
3. 方法
4. 決定的な記録
5. 予想との差
6. 結論と限界
7. 次に試したいこと

一枚一メッセージにし、最大20分へ収める。最も見せたい証拠を先に特定してから枚数を決める。

終了条件：各スライドの役割と想定時間が並ぶ。

## 8. 表示と読み上げを作る

同じ情報を重複させず役割を分ける。

- 主画面：結論、図、写真、短いキーワード
- 読み上げ：順序、因果、画面だけでは不足する説明
- BIIM右欄：読み飛ばしても成立する補足、作者コメント、条件、追加表

読み上げの一segmentは一つの表示段階に対応させる。画面にない数値や固有名詞は字幕でも確認できるようにする。

終了条件：無音でも要点が分かり、音声を加えると理解が深まる。

## 9. 評価と通し練習

評価基準を使い、最優先の弱点を一つ直す。通し練習では時間、操作ミス、聞き取りにくさ、読めない箇所を記録する。

終了条件：必須条件を満たし、残る弱点を本人が説明できる。

## 行き詰まったとき

- 答えが広い：具体的な直近一回を聞く。
- 答えが出ない：選択肢を3つ示す。
- 候補を選べない：面白さ、実行可能性、記録の残しやすさを各0〜2で仮比較する。
- 結果が出なかった：「なぜ出なかったか」「方法で分かったこと」を研究対象へ戻せるか考える。
- 発表を先に作りたがる：仮構成として作り、未取得の証拠を明記する。
