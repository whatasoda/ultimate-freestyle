# UX改善ログ 2026-07-29

## 対象となる利用者の流れ

1. Twitchでログインする。
2. AIクライアントとの対話から研究を作る。
3. Web UIで研究内容と画像を確認・微調整する。
4. 一枚編集画面でスライド、見た目、読み上げを調整する。
5. 必要ならVOICEVOX音声を生成する。
6. 固定プレビューを確認して公開する。

## 初回監査で見つかった課題

| 優先度 | 課題 | 影響 |
|---|---|---|
| 最優先 | 同じ画面にある複数フォームのversionが相互に同期されない場合がある | 連続編集の2回目が競合し、初心者には原因が分からない |
| 最優先 | 発表設定の変更後にプレビューが古いことを必ずしも表示しない | 変更前の版を誤って公開し得る |
| 高 | VOICEVOX設定後の未生成区間がプレビューを塞ぐ | ブラウザ音声フォールバックがあるのに制作を進められない |
| 高 | プロジェクト詳細に機能が並ぶだけで、次の操作が分からない | 研究から公開までの現在地を利用者自身が推測する必要がある |
| 高 | 未保存のまま別画面へ移動できる | 入力内容を失う |
| 中 | AIでしかできない操作の依頼文を利用者が考える必要がある | AI Agentを初めて使う人ほど開始しづらい |

## 改善ループ1

- ページ内の全編集フォームでproject versionを同期する共通処理へ統合した。
- どの編集フォームを保存しても、既存プレビューを要再生成として扱うようにした。
- 未保存フォームがある状態でページを離れる場合にブラウザ警告を出すようにした。
- VOICEVOX未生成区間があっても、ブラウザ音声で固定プレビューを作成できるようにした。
- 研究内容、発表構成、プレビュー、公開の4段階と次の操作を示す進行パネルを追加した。
- AIへ依頼する文章をコピーできる導線を、研究が空の場合とスライド未作成の場合に追加した。

## 次の監査候補

- プロジェクト詳細の情報重複と縦方向の長さ。
- スライド編集画面で設定変更結果を保存前に比較する方法。
- 音声生成画面における必須操作と任意調整の区別。
- 公開直前に見るべき品質項目の集約。
- キーボード操作、フォーカス移動、読み上げ向け状態通知。

## 改善ループ2

- 問い・仮説・方法の読み取り専用再掲を削り、研究本文の編集場所を一つにした。
- 「わかったこと」と「限界・今後の課題」をWeb UIから1行1件で編集できるようにした。
- 入力済みの研究では研究内容フォームを折りたたみ、必要なときだけ開く構成にした。
- 発表比率と0ページ目の設定を折りたたみ、通常の確認・公開導線を短くした。
- 長いスライド一覧を専用スクロール領域へ収めた。
- 研究内容の保存後は画面を再読込し、見出し、進行状況、次の操作が古いまま残らないようにした。

## 改善ループ3

- 音声生成が公開の必須条件に見える説明を削り、ブラウザ音声で先へ進めることを明記した。
- ずんだもん、四国めたん、春日部つむぎの標準的な声をワンクリックで選べる導線を追加した。
- 118種類の一覧は残し、詳しい利用者が全話者・スタイルを選べる状態を維持した。
- 読み上げ区間を「すべて・要生成・生成済み・失敗」で絞り込めるようにした。
- 最初に開く区間を先頭固定から、最初に対応が必要な区間へ変更した。

## 改善ループ4

- 一枚編集画面の上部に前後のスライドへ移動する導線を追加した。
- 連続して内容を整えられるように「保存して次へ」を追加した。
- 現在のスライドをフィルムストリップ内へ自動スクロールするようにした。
- 本文、補足欄、文章量プリセットの名称を、用途が判断できる表現へ変更した。
- 本文がMarkdownと自由構成時の代替表示を兼ねること、補足欄が読み上げ対象外であることを編集場所に明記した。

## 改善ループ5

- 文字数制限のある文章欄へ現在値と上限のカウンターを追加し、上限の90%から注意色で示すようにした。
- 入力中のフォームを `Cmd/Ctrl + S` で保存できるようにした。
- 通信中のボタンに `aria-busy` を付け、単に選べないボタンとの待ちカーソルを区別した。
- リンク、ボタン、入力欄、開閉見出しへ共通のキーボードフォーカス表示を追加した。
- OSの「視差効果を減らす」設定では、Web UIのanimationとtransitionも実質停止するようにした。

## 改善ループ6

- 公開操作の直前に、研究の問いと方法、表紙、画像説明、読み上げ文、想定時間、固定プレビューを一覧化した。
- 各項目に現在の件数や時間を表示し、どこを確認すべきか判断できるようにした。
- 表紙や読み上げをあえて使わない研究もあるため、未設定項目は注意として示し、プレビュー作成を一律には止めない設計にした。
- 現在の固定プレビューがない場合はチェックリストを自動で開き、確認済みなら折りたたむようにした。

## 改善ループ7

- スライド面のクリックでも次のSTEPへ進めるようにし、0ページ目に操作方法を表示した。
- 音声のないSTEPや読み上げを無効にした状態でも、想定秒数に基づいて自動送りが動くようにした。
- 自動送りは読み上げがある場合は読み終わりを待ち、ない場合はスライドの想定時間を段階数で分配して進む。
- 音声と自動送りのボタンへON/OFFを明記し、有効状態を色でも判別できるようにした。
- 発表画面のボタンと音量入力にキーボードフォーカス表示を追加した。

## 改善ループ8

- 研究一覧へタイトル・制作段階の絞り込みを追加した。
- 入力に応じて表示件数を更新し、一致しない場合は空の結果であることを明示するようにした。
- 検索はサーバー通信を発生させず、最大20件の表示済みカードを即時に絞り込む構成とした。

## 改善ループ9

- 画像を送信する前に、サムネイル、ファイル名、容量をその場で確認できるようにした。
- 対応形式と10MiB上限をファイル選択時に検査し、問題をアップロード前に日本語で示すようにした。
- 保存時にWeb向けへ圧縮されることと、内容を伝える画像には説明が必要なことを入力場所に明記した。
- 画像削除の処理中・成功・失敗をカード内で通知し、失敗時のalert依存をなくした。

## 改善ループ10

- 一枚編集画面に、左右の一覧・設定欄を一時的に隠す「プレビューを広げる」を追加した。
- 集中表示中も入力中の内容はDOM上に保持し、「編集欄を戻す」で同じ場所へ復帰できるようにした。
- 集中表示の選択をlocalStorageに記録し、スライドを移動しても好みの作業幅を維持するようにした。
- 別タブで開く操作は「別画面で開く」と明示し、画面内の集中表示と区別した。

## 改善ループ11

- 発表画面のフッターを狭い画面では2段へ組み替え、進捗と操作ボタンが横にはみ出さないようにした。
- 680px以下では優先度の低い音声クレジットを隠し、前後移動、音声、自動送り、音量を維持した。
- 430px以下では音量を独立した行へ移し、4つの主要ボタンを均等幅にした。
- スマートフォンで押しやすいよう、主要ボタンの高さを42px以上へ拡大した。
- 長い研究タイトルが経過時間を押し出さないよう、ヘッダー内で省略表示するようにした。

## 改善ループ12

- MCP tool一件の入力schema上限に加え、tool数と`tools/list`契約全体のJSON容量にも回帰テストを追加した。
- 対応AIクライアントが全tool定義を一度に読む場合を想定し、38 tool以下・160KB未満を現在の上限とした。
- preset作成と部分更新で代替できる大きな`upsert_presentation_template`を削除し、tool数と一度に渡す引数を減らした。
- 全データ取得と評価は標準MCP resourceへ移し、一枚取得用の`research://projects/{id}/slides/{slideId}`も追加した。
- `create_project`は空の研究全体ではなくsummaryだけを返すようにし、`tools/list`の実測JSONを338,689 byteから157,045 byteへ削減した。
- 今後の機能追加では、既存toolの部分更新で表現できないかを先に検討し、引数とtool一覧の再肥大化をテストで検知できるようにした。

## 改善ループ13

- 研究一覧に、対応AIクライアントへRemote MCPを登録する3段階の案内を追加した。
- 本番MCP URLをワンクリックでコピーでき、研究がまだない利用者には案内を最初から開いて表示する。
- クライアントごとに設定名称が異なることを伝え、Codex、ChatGPT、Claudeのいずれにも通じる説明にした。
- TwitchのパスワードやtokenをAIへ貼らず、認証画面でログインすることを明記した。

## 改善ループ14

- 0ページ目を無効にした発表で、ブラウザの自動再生制限によりVOICEVOX音声が拒否される場合を明示的に扱うようにした。
- `NotAllowedError`では別の声へ自動fallbackせず、発表枠内に「音声を開始」を表示して同じ生成音声を再試行する。
- ボタンだけでなく発表枠のクリックでも、音声待ちの間はページを進めず音声開始を優先する。
- Web Speech側が同じ理由で拒否された場合も同じ復帰導線を表示するようにした。

## 改善ループ15

- 発表ヘッダーの時間を「実経過・現在位置の目安・想定合計」の3つに分けて明示した。
- 想定経過をSTEP開始時刻からSTEP完了目安へ変更し、段階のない最終スライドでも合計予定時間へ到達するようにした。
- 狭い画面ではラベルと合計を省略し、実経過と目安の2値を維持して発表枠を圧迫しないようにした。

## 改善ループ16

- 最後のスライドから先へ進んだとき、無反応にせず発表完了画面を表示するようにした。
- 完了画面からは最初から見直すか、最後のスライドへ戻るかを選べるようにした。
- 完了時は自動送りを停止し、意図せず操作が続いているように見えない状態にした。

## 改善ループ17

- 発表操作欄の音量をスライダーだけでなく割合でも表示し、現在値を読み取れるようにした。
- localStorageから復元した値を0〜100%の範囲へ正規化し、不正な保存値では100%へ安全に戻すようにした。
- スライダー操作中は再生中の生成音声と割合表示を即時に同期するようにした。

## 改善ループ18

- 0ページ目が最初の2音声しか事前確認していなかった制限を外し、発表で使う全生成音声を対象にした。
- 画像・音声・フォントの読み込みを最大4並列に抑え、素材数が増えても通信を一度に集中させないようにした。
- 10秒で発表開始を可能にする既存の上限は維持し、遅い素材が一つあっても発表全体を止めない構成にした。

## 改善ループ19

- ブラウザ読み上げが自動再生制限以外の理由で失敗した場合、自動送りが黙って停止せず想定時間後に進むようにした。
- ページ移動で中断した古い読み上げの終了・エラーイベントを世代番号で無視し、次ページの進行へ干渉しないようにした。
- 自動再生制限だけは従来どおり「音声を開始」を表示し、音声なしで勝手に進めない動作を維持した。
