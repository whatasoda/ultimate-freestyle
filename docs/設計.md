## 目的

このリポジトリには複数の研究候補を蓄積する。一方、発表時には研究ごとに独立したWebスライドとして開き、別の研究へ移動するナビゲーションは表示しない。

```text
researches/
  registry.ts             発表可能な研究の登録簿
  <slug>/
    deck.tsx              発表スライド
    README.md             問い・方法・結果・素材・進捗

public/researches/
  <slug>/                 画像・動画などの静的素材。VOICEVOX音声はActionsで配置

components/presentation/  全研究で共有する発表機能
docs/                     企画前提と設計
```

## URL

- `/`：現在の標準テンプレート
- `/present/<slug>`：登録された研究を直接表示

発表物間のリンク一覧や選択UIは作らない。必要なURLは配信前にブックマークやブラウザタブとして準備する。

## 公開方式と基準パス

標準の公開方式はGitHub ActionsからのGitHub Pagesとする。アプリは静的書き出しし、成果物 `dist/client/` をPages artifactとして公開する。Cloudflare向けの通常ビルドは残し、GitHub Pages向けビルドだけ `output: "export"` を有効にする。

通常のプロジェクトPagesは `/repository-name` 配下、カスタムドメインは `/` 配下になる。ワークフロー内の `actions/configure-pages` が返す `base_path` を `PAGES_BASE_PATH` として受け取り、Viteの静的asset URLとブラウザで読む `public/` 素材URLへ適用する。公開URLやリポジトリ名をコードへ固定しない。

Nextのルーティング用 `basePath` は使用しない。現行Vinextの静的書き出しでは、動的ルートの事前生成と `basePath` の併用が安定しないためである。このプロジェクトでは研究間をNext Routerで移動せず、各研究のHTMLを `generateStaticParams` から個別生成する。ページ内の進行はクエリ文字列とHistory APIで完結する。

`audioSrc` 等の公開素材は `/researches/...` の形で研究データへ記述し、実際の公開時には共通のURL解決処理が `PAGES_BASE_PATH` を付ける。外部の完全URLは変更しない。

## 進捗の意味

発表画面の進捗は、単なるスライド枚数ではなく、スライド表示と段階表示を1単位ずつ数えて算出する。このため、同じスライド内で要素を順に出している間も進捗が増える。

予定経過時間は、完了したスライドの `durationSeconds` と、現在の段階表示の割合から算出する。実経過時間は発表者がタイマーを開始した時点から計測する。

## 発表画面の枠

発表内容は16:9または4:3の枠に収め、画面サイズに応じて選択比率を維持したまま拡大・縮小する。研究名とタイマーは枠の上、発表進捗・音声進捗・操作ボタンは枠の下に配置し、発表内容へ重ねない。全画面表示を選んだ場合も発表枠と外部コントロールの関係は維持する。

レイアウトは研究データを変えずに切り替えられる共通層として実装する。

- `cinematic`：大きな文字、背景図形、余白を使う演出重視の標準形。
- `biim`：主画面、右情報欄、下字幕欄を固定分割する解説重視の形。
- `minimal`：白地と罫線を使い、内容を読むことに集中させる資料重視の形。

deckの `layout` を既定値とし、枠外の選択UIから一時的に変更できる。選択値は `layout` クエリへ保存し、比較用URLを共有できるようにする。

BIIM右情報欄はスライドの `sidebar` に任意のReact要素として記述する。この情報は読み上げ原稿とは分離し、音声生成の対象にしない。作者コメント、追加データ、注意事項、画像など、視聴者が任意に読む補足情報を想定する。未指定時はスライド番号・段階・予定時刻を表示する。

## スライド構成モード

一つのdeckでは、用途に応じてスライド単位で次の3形式を混在できる。

- `flow`：タイトル、markdown本文、BIIM補足欄からなる定型構成。
- `canvas`：百分率座標でblockを絶対配置する単純な自由配置。
- `scene`：登録済みWeb Componentsを入れ子にしてリッチな画面を構成する標準の自由構成。

flowは短文専用にせず、一言強調、標準、読み物、2段組み、高密度の組版presetを一枚ごとに選べる。presetは本文・見出し倍率、行間、段落間隔、段数、段間、縦横揃えの安全な既定値を持ち、必要な値だけを上書きする。最大3段まで対応し、見出しと段落は途中で分断しにくいCSS組版を使う。文章量と見出し・段落構造から用途違いのpresetを検出し、実rendererが70%未満まで自動縮小した場合もWeb UIの品質確認へ警告する。文章量が多い場合は自動fitだけに頼らず、先に組版と段数を選び、それでも収まらない内容は複数スライドへ分割する。Web UIとMCPの`update_slide_typography`はこの設定だけを個別更新する。

### canvas

定型の本文・補足欄に収まらないスライドは、スライド単位で`composition.mode = "canvas"`を指定する。選択した発表枠を百分率座標のcanvasとして扱い、markdown、project画像、矩形・楕円・線を任意の位置と重なり順で配置できる。従来のflowスライドと同じdeck内で混在できる。

各blockは`frame`、`z_index`、表示段階`at`、animation presetと検証済みstyle tokenを持つ。MCPでは`set_slide_canvas`、`edit_slide_block`、`delete_slide_block`を使う。作成時は安全な既定配置から始め、更新時は一fieldだけを送り、slide全体やblock全体を送り直さない。

任意HTML、JavaScript、CSS、外部画像URLは受け付けない。画像はupload済みの`asset_id`だけを参照し、preview生成時にrevision専用R2 objectへ固定する。これにより元画像を後から削除しても、確認済み・公開済みの版は変化しない。1 revisionあたり画像30件・合計30 MiB、HTML 2 MiBを上限とする。

自由配置でも読み上げ、段階進行、URL、音量、自動送りは共通runtimeが管理する。rendererは`data-block-id`、`data-block-kind`、`data-reveal-at`、`data-animation`を出力し、将来のWeb editorや演出拡張が同じschemaを利用できるようにする。

### sceneと登録Web Components

ローカル版に近い表現が必要な一枚は`composition.mode = "scene"`とし、正規化されたnode treeを保存する。`layer`、`stack`、`grid`を親にして、`hero`、`markdown`、`quote`、`card`、`metric`、`callout`、`bar_chart`、`timeline`、project画像、図形を組み合わせる。`stack`と`grid`は自動配置、`layer`の子だけは百分率frameを持つ。

MCPでは`set_slide_scene`で切り替え、`create_slide_component`で安全な既定値から一件ずつ作る。内容は`update_slide_component_content`、グラフとtimelineの項目は`edit_slide_data_item`、配置と見た目は`update_slide_component`で一項目ずつ変更し、component全体や本文を再送しない。編集前には`research://projects/{id}/slides/{slideId}/elements/{elementId}`で対象一件を読む。component一覧と構成規則は`research://guide/presentation-components` resourceへ分離する。各nodeとグラフ・timelineのitemは表示段階`at`を持ち、共通runtimeのクリック進行とanimationへ連携する。

研究全体の読取は`research://projects/{id}`、発表全体は`research://projects/{id}/deck`、一枚だけの再取得は`research://projects/{id}/slides/{slideId}`を使う。全量データをtoolの入出力schemaへ含めず、変更操作だけを小粒度toolとして公開する。`tools/list`は38件以下・160KB未満、一件のinput schemaは12KB未満をcontract testで固定する。

rendererはプラットフォームが所有するversion付き`uf-runtime@1`と`uf-*` custom elementだけを生成する。文字列はescapeし、styleは検証済みtoken、画像はprojectの`asset_id`だけを受け付ける。Shadow DOMやWeb Components自体をセキュリティ境界とは見なさず、任意HTML、CSS、JavaScriptは親documentで実行しない。将来ユーザーコードを扱う場合は、cookieを持たない別originと`iframe sandbox`、厳格なCSP、制限付きmessage protocolを先に用意する。

### 一枚編集Web UI

研究詳細から各スライドを開くと、左にfilmstrip、中央に選択比率の実renderer、右に内容・デザイン・読み上げ・構造・品質確認を置いた一枚編集画面を表示する。中央は公開rendererと同じコードを`iframe`で描画し、編集用frameだけ`frame-ancestors 'self'`と`X-Frame-Options: SAMEORIGIN`を設定する。公開HTMLは従来どおり埋め込み不可とする。

基本文言とBIIM補足に加え、slide template、tone、animation、templateのvisual・font・density・配色・領域・余白・motion、読み上げ枠、segment別話者・VOICEVOX profile・7種の調声値をWeb UIから保存できる。各APIはCSRF、96 KiB以下のJSON上限、schema検証、`expected_version`による競合防止を適用する。研究内容は題名・問い・方法・発見・限界を独立保存し、短い修正で他の長文を再送しない。componentの追加・構造編集は現段階ではMCPを正本とし、Web UIは全設定のoutlineと正確な見た目を確認する。表示stepはsame-originの固定message schemaで切り替え、iframeを再読込しない。

sceneの構成outlineは保存配列の順ではなく、親子関係と`order`から木構造として表示する。各componentには自動配置／自由配置と表示STEPを併記する。中央iframeを保存後またはSTEP切替後に再読込している間は、黒い空欄に見えないよう読み込み中のフィードバックを表示する。

読み上げsegmentは一枚編集Web UIでもSTEPごとに追加・削除でき、文言、表示話者、VOICEVOX profile、7種の調声値を修正できる。追加前の原稿も対象STEPの実rendererへ表示し、ブラウザ仮試聴と概算時間を確認する。原稿、profile、調声値が変わったsegmentの`audio_src`は保存時に`null`へ戻し、古い設定から生成した音声を再利用しない。画面にはVOICEVOX標準値、profile基準値、segment上書き値から解決した実効値と、生成音声／browser fallbackの状態を表示する。

rendererは16:9または4:3のstageをsize containerとし、flow、canvas、scene、読み上げ欄の寸法をstage基準で計算する。font読込後とresize後に本文、補足、字幕、leaf componentを測定し、安全な下限まで自動fitする。それでも残るoverflowは編集frameから親画面へ対象付きで通知し、品質確認欄へ表示する。公開画面には編集用警告を出さない。表紙前の0ページ目は画像・生成音声・fontを事前読込し、開始クリック後に実経過時間と初回読み上げを始める。0ページ目はslide数、発表進捗、想定時間には含めない。

## 進行位置とURL

現在位置は `?slide=<1始まり>&step=<0始まり>` としてURLへ保存する。手動送りと自動送りのどちらも `history.pushState` で履歴へ追加し、ブラウザの戻る／進むでは `popstate` から表示位置を復元する。範囲外の値は存在する最後のスライド・段階へ補正する。URLが進捗の正本であり、進行位置は `localStorage` へ重複保存しない。レイアウトは同じURLの `layout` へ保存する。

## 音声の段階的な実装

1. 通常開発：`bun run dev` では音声ファイルを要求せず、ブラウザ標準読み上げで原稿を確認する。
2. ローカル確認：VOICEVOX ENGINEとffmpegを用意できる場合だけMP3を生成し、Git対象外のプレビュー領域で確認する。
3. 試験公開：`voice-*` タグまたは手動実行からGitHub Actions上で変更segmentだけをMP3化し、そのrunからPagesへ公開する。

音声は補助機能とし、音声が再生できなくてもスライドだけで発表が成立するようにする。外部サービスへの実行時依存は持たせない。

## 読み上げ原稿と画面表示

読み上げ原稿は音声専用データにせず、必ず視聴者が文字でも読めるようにする。表示文と合成音声の原稿は `narration.segments[].text` を単一の情報源とする。

段階表示の `at` ごとに原稿を分割し、クリック後に表示されている内容と読み上げ対象を一致させる。

- `dialogue`：ADV風の会話枠。内容領域と重ならないよう、下部に専用スペースを確保する。
- `commentary`：ゆっくり実況等を想定した大きな字幕。短くテンポのよい文にする。
- `inline`：固定高の全文欄に原稿を配置し、現在の段落へ追従する。
- `subtitle`：映像字幕風のコンパクトな下字幕。
- `minimal`：主画面を隠しにくい最小限の字幕。

rendererは上記の値を見た目にも反映し、話者nameplate、配置、寸法、文字揃え、話者表示、進捗表示、文字倍率、最大行数を検証済みtokenから設定する。表示はrenderer既定、deck既定、slide設定の順に解決する。どの方式でも「ナレーション」のような固定ラベルを発表枠内へ追加せず、字幕本文そのものを表示する。

音声ファイルをVOICEVOX等で生成する場合も、segmentごとにファイルを分ける。スライドや段階を戻ったときは再生中の音声を停止し、現在の原稿だけを再生する。

読み上げ音量は0〜100%で調整し、`ultimate-freestyle:narration-volume` をキーとして `localStorage` に保存する。音声ファイルには再生中にも適用し、Web Speech APIの読み上げには次のsegmentから適用する。保存が利用できない環境でも、開いている間の音量変更は有効にする。

ページまたは段階を進めたときは、対応するsegmentを自動再生する。再生位置と全体時間は下部のインジケーターに表示する。個別の再読み上げボタンは持たず、聞き直す場合は一度前へ戻ってから再度進む。自動送りを有効にした場合は音声終了後に次へ進み、音声がない段階では短い待機時間を使う。

一括生成は `bun run voicevox:generate -- <slug>` を使う。既定の出力は
`public/.voicevox-preview/researches/<slug>/audio/<slide-id>-<at>.mp3` で、
モノラル64kbpsとする。プレビュー領域、ENGINE、音声モデルはリポジトリへ含めない。
ローカル確認は `bun run dev:voicevox` を使い、通常の `bun run dev` は常にブラウザ音声を使う。

VOICEVOXはdeckの`voicevox.profiles`へ最大16個のtalk profileを定義する。参照の正本は`speakerUuid + styleId`とし、話者名・style名は表示用snapshotとして扱う。deck既定profileに加え、segmentの`voiceProfileId`で切り替え、`voiceTuning`で話速、音高、抑揚、音量、ポーズ、前後無音を上書きできる。使用profileからVOICEVOXクレジットを自動表示する。

生成manifestはv2とし、原稿、UUID、style ID、全調声値、ENGINE build／version、core version、話者version、catalog、ユーザー辞書、codec設定をfingerprintへ含める。`audioSrc`は正本ではなく、このfingerprintから再生成できるcacheとする。

GitHub Actionsでの生成は通常のpushから分離する。明示的な `voice-*` タグと
`workflow_dispatch` だけをトリガーにし、原稿、話者、生成設定、ENGINEバージョンの
fingerprintが一致するMP3をキャッシュから再利用する。キャッシュが失効した場合は再生成する。
生成runはMP3を7日間のartifactとして残し、同じrunでPagesへ試験公開するが、自動コミットはしない。

`main` pushのPages workflowはVOICEVOXを起動しない。利用可能なキャッシュのうち、現在の
`narration.segments[].text` のハッシュと一致するMP3だけを配置し、それ以外はブラウザ読み上げへ
フォールバックする。これにより古い原稿の音声を誤って公開しない。

## 音声ファイルの保管

- 生成途中のWAVはffmpeg変換用の一時ファイルであり、処理後に削除する。
- ローカル確認用MP3とActionsキャッシュはGitへ含めない。
- Actions artifactは試聴用で、永続保管先やGitへ取り込むための受け渡しには使わない。
- 本番用MP3もActionsだけで生成してPages成果物へ配置し、リポジトリには含めない。
- Git LFSはGitHub Pages配信と相性が悪いため、この用途では使用しない。
- 音声の正本は原稿、話者・話速等の設定、ENGINEバージョンであり、キャッシュ失効時にも再生成可能な状態を維持する。
