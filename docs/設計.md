# 設計と管理方針

> **現行構成（2026-07-30）**: 公開基盤はCloudflare Worker + D1 + private R2である。Remote MCPとWeb UIは`saijiyu-kenkyu.2764.moe`の同一hostでpath分離し、main pushはGitHub Actionsから検証、D1 migration、Worker deploy、本番smokeを行う。インフラの正本は`docs/remote-mcp-plan.html`、個別判断は`docs/decisions/`とする。

## 目的

このリポジトリには複数の研究候補を蓄積する。一方、発表時には研究ごとに独立したWebスライドとして開き、別の研究へ移動するナビゲーションは表示しない。

研究データはD1のversion付きdocumentを正本とし、画像、VOICEVOX cache、固定previewはR2へ保存する。共有schemaは`packages/research-schema/`、MCP・Web UI・renderer・公開処理は`apps/mcp-server/`で管理する。

## URL

- `/dashboard`：Twitchログイン中の利用者の研究一覧
- `/dashboard/projects/<id>`：研究詳細、音声、スライド編集、preview・公開操作
- `/dashboard/projects/<id>/review?slide=<slide-id>`：実表示、画面テキスト、音声原稿、範囲付きコメントを並べるレビュー画面
- `/preview/<revision-id>`：所有者が確認する固定preview
- `/p/<slug>`：公開中の固定revision

発表物間のリンク一覧や選択UIは作らない。必要なURLは配信前にブックマークやブラウザタブとして準備する。

## 公開方式

固定preview作成時に研究version、renderer version、参照画像、生成済み音声をrevisionへ固定し、HTMLと素材をprivate R2へ保存する。所有者が終了画面まで確認した現在versionのpreviewだけを`/p/<slug>`へ切り替えられる。下書き編集、renderer更新、元画像・音声cacheの削除は公開済みrevisionを変更しない。GitHub Pagesとの二重公開や基準path互換層は持たない。

## 進捗の意味

発表画面の進捗は、単なるスライド枚数ではなく、スライド表示と段階表示を1単位ずつ数えて算出する。このため、同じスライド内で要素を順に出している間も進捗が増える。

予定経過時間は、完了したスライドの`duration_seconds`と、現在の段階表示の割合から算出する。実経過時間は発表者がタイマーを開始した時点から計測する。

## 発表画面の枠

発表内容は16:9または4:3の枠に収め、画面サイズに応じて選択比率を維持したまま拡大・縮小する。研究名とタイマーは枠の上、発表進捗・音声進捗・操作ボタンは枠の下に配置し、発表内容へ重ねない。外枠のgrid列は最小幅を0として、狭い画面でも操作ボタンの内容幅に発表枠全体を押し広げさせない。全画面表示を選んだ場合も発表枠と外部コントロールの関係は維持する。

レイアウトは研究データを変えずに切り替えられる共通層として実装する。

- `cinematic`：大きな文字、背景図形、余白を使う演出重視の標準形。
- `biim`：主画面、右情報欄、下字幕欄を固定分割する解説重視の形。
- `minimal`：白地と罫線を使い、内容を読むことに集中させる資料重視の形。

deckの `layout` を既定値とし、枠外の選択UIから一時的に変更できる。選択値は `layout` クエリへ保存し、比較用URLを共有できるようにする。

BIIM右情報欄はflowの`sidebar_markdown`またはsceneの登録componentで構成する。この情報は読み上げ原稿とは分離し、音声生成の対象にしない。作者コメント、追加データ、注意事項、画像など、視聴者が任意に読む補足情報を想定する。

## 研究ごとのデザインシステム

visual presetは完成形ではなく、安全な配色・文字・余白から編集を始めるための出発点とする。利用者はproject内に最大16件のtemplateを作り、研究テーマ、作者の好み、避けたい表現を1,000文字以内の`design_notes`へ記録できる。この文は発表画面へ表示せず、Web UIとAI Agentが個別設定を同じ意図へ揃えるために使う。

templateは配色、font、密度、領域、余白、動きに加え、背景モチーフ、見出し処理、画像処理、カード・補足欄処理を独立した検証済みtokenとして持つ。背景モチーフはなし、点、方眼、斜線、同心円、波から選び、色、濃さ、大きさを調整する。見出しは装飾なし、アクセント線、マーカー、囲み、縁取り、画像は素材のまま、角丸、額装、モノクロ、カード・補足欄は素のまま、やわらかい面、線で囲む、浮き上がる、ガラスから選ぶ。任意CSSを受け付けず、プリセットを変更しなくても各軸を組み替えられるようにする。

一つのtemplateは基本デザインに加え、表紙、章扉、本文、比較、結果、結びの6役割へ差分を持てる。役割差分はvisual preset、領域、配色、font、密度、余白、角丸、文字組み、モチーフ、見出し、画像、カード・補足欄、animationを上書きでき、未指定値は基本デザインを継承する。同じ研究の一貫性を保ったまま「結果だけ発見を示す暖色と強い動き」「章扉だけ中央集中とdisplay書体」のような意味のある変化を作り、役割ごとにtemplateを複製しない。slideの`role`は見た目だけでなくfilmstrip、検索、設定概要でも常に表示する。

template変更は既定を継承するスライドと直接指定するスライドへ即時反映する。一枚だけ例外を作る場合はcanvas／sceneのcomponent styleを使う。Web UIは保存前の文言、組版、基本デザイン、役割差分、読み上げ枠、componentを80msの入力待ち後に同一rendererへ送り、中央プレビューから適用完了を受け取って「保存すると確定」と表示する。役割を切り替えるときは直前の役割差分を下書きへ退避してから、新しい役割を現在スライドで比較する。MCPは`update_presentation_template_fields`で最大8項目ずつ部分更新し、`role`を指定した場合は役割差分だけを更新する。役割差分では`null`を送るとその項目を削除して基本へ戻す。

AI Agentは`research://guide/presentation-design-workflow`を正本として、研究内容と既存deckから4行以内のdesign briefを作り、色以外の情報階層も異なる3方向を変更前に比較する。採用後だけ`design_notes`、基本template、役割差分、一枚固有のcomponentを小粒度toolで変更し、deck resourceを再読する。`refine_presentation_design` promptは提案、適用、監査の3 modeを持つ。Web UIは同じ手順を依頼する文と9/10監査文をコピーできる。研究本文、証拠、読み上げ原稿は見た目調整の副作用として変更しない。

## スライド構成モード

一つのdeckでは、用途に応じてスライド単位で次の3形式を混在できる。

- `flow`：タイトル、markdown本文、BIIM補足欄からなる定型構成。
- `canvas`：百分率座標でblockを絶対配置する単純な自由配置。
- `scene`：登録済みWeb Componentsを入れ子にしてリッチな画面を構成する標準の自由構成。

flowは短文専用にせず、一言強調、標準、読み物、2段組み、高密度の組版presetを一枚ごとに選べる。presetは本文・見出し倍率、行間、段落間隔、段数、段間、縦横揃えの安全な既定値を持ち、必要な値だけを上書きする。最大3段まで対応し、見出しと段落は途中で分断しにくいCSS組版を使う。文章量と見出し・段落構造から用途違いのpresetを検出し、実rendererが70%未満まで自動縮小した場合もWeb UIの品質確認へ警告する。文章量が多い場合は自動fitだけに頼らず、先に組版と段数を選び、それでも収まらない内容は複数スライドへ分割する。Web UIとMCPの`update_slide_typography`はこの設定だけを個別更新する。

### canvas

定型の本文・補足欄に収まらないスライドは、スライド単位で`composition.mode = "canvas"`を指定する。選択した発表枠を百分率座標のcanvasとして扱い、markdown、project画像、矩形・楕円・線を任意の位置と重なり順で配置できる。従来のflowスライドと同じdeck内で混在できる。

各blockは`frame`、`z_index`、表示段階`at`、animation presetと検証済みstyle tokenを持つ。MCPでは`set_slide_canvas`、`edit_slide_block`、`delete_slide_block`を使う。作成時は安全な既定配置から始め、更新時は一fieldだけを送り、slide全体やblock全体を送り直さない。

任意HTML、JavaScript、CSS、外部画像URLは受け付けない。画像はupload済みの`asset_id`だけを参照し、preview生成時にrevision専用R2 objectへ固定する。これにより元画像を後から削除しても、確認済み・公開済みの版は変化しない。1 revisionあたり画像30件・合計30 MiB、HTML 2 MiBを上限とする。

自由配置でも読み上げ、段階進行、URL、音量、自動送りは共通runtimeが管理する。rendererは`data-block-id`、`data-block-kind`、`data-reveal-at`、`data-animation`を出力し、将来のWeb editorや演出拡張が同じschemaを利用できるようにする。

### sceneと登録Web Components

ローカル版に近い表現が必要な一枚は`composition.mode = "scene"`とし、正規化されたnode treeを保存する。`layer`、`stack`、`grid`を親にして、`hero`、`markdown`、`quote`、`card`、`metric`、`callout`、`bar_chart`、`timeline`、project画像、図形を組み合わせる。`stack`と`grid`は自動配置、`layer`の子だけは百分率frameを持つ。

MCPでは`set_slide_scene`で切り替え、`create_slide_component`で安全な既定値から一件ずつ作る。主張＋根拠、2案比較、3数値、経過・手順は同じtoolの`pattern-*`を指定すると、複数の通常componentからなる編集可能なまとまりを一回のversion更新で作れる。patternは固定テンプレートではなく、追加後に子を個別編集でき、rootの移動で子孫も一緒に移る出発点とする。Web UIでrootを複製すると全子孫のIDと親参照を付け替えた独立したまとまりを作り、まとまり削除は対象件数の確認後に全子孫を一括削除する。MCPの`delete_slide_component`は通常の一件削除を既定とし、明示的な`include_descendants: true`だけ一括削除を許可する。内容は`update_slide_component_content`、グラフとtimelineの項目は`edit_slide_data_item`、配置と見た目は`update_slide_component`で一項目ずつ変更し、component全体や本文を再送しない。編集前には`research://projects/{id}/slides/{slideId}/elements/{elementId}`で対象一件を読む。component一覧と構成規則は`research://guide/presentation-components` resourceへ分離する。各nodeとグラフ・timelineのitemは表示段階`at`を持ち、共通runtimeのクリック進行とanimationへ連携する。

研究全体の読取は`research://projects/{id}`、発表全体は`research://projects/{id}/deck`、一枚だけの再取得は`research://projects/{id}/slides/{slideId}`を使う。全量データをtoolの入出力schemaへ含めず、変更操作だけを小粒度toolとして公開する。`tools/list`は36件以下・90KB未満、一件のinput schemaは8KB未満をcontract testで固定する。

rendererはプラットフォームが所有するversion付き`uf-runtime@1`と`uf-*` custom elementだけを生成する。文字列はescapeし、styleは検証済みtoken、画像はprojectの`asset_id`だけを受け付ける。Shadow DOMやWeb Components自体をセキュリティ境界とは見なさず、任意HTML、CSS、JavaScriptは親documentで実行しない。将来ユーザーコードを扱う場合は、cookieを持たない別originと`iframe sandbox`、厳格なCSP、制限付きmessage protocolを先に用意する。

### 一枚編集Web UI

研究詳細から各スライドを開くと、左にfilmstrip、中央に選択比率の実renderer、右に内容・デザイン・読み上げ・構造・品質確認を置いた一枚編集画面を表示する。デスクトップでは3列を同じviewport内へ固定し、filmstrip、preview、inspectorを独立して追えるようにする。狭い画面では2列を経て、モバイルではタブで一領域ずつ表示し、inspectorも選択した項目だけを表示する。選択されていない項目を閉じたdetailsとして残さず、タブの選択状態と表示中のtabpanelを一致させる。中央は公開rendererと同じコードを`iframe`で描画し、編集用frameだけ`frame-ancestors 'self'`と`X-Frame-Options: SAMEORIGIN`を設定する。公開HTMLは従来どおり埋め込み不可とする。

基本文言とBIIM補足に加え、slide template、role、tone、animation、templateのデザイン方針・visual・font・density・配色・領域・余白・motion・モチーフ・見出し・画像処理・カード処理・役割差分、読み上げ枠、segment別話者・VOICEVOX profile・7種の調声値をWeb UIから保存できる。役割差分の編集欄は、差分がある役割、継承中の値、役割適用後のコントラストを同時に表示する。各APIはCSRF、128 KiB以下のJSON上限、schema検証、`expected_version`による競合防止を適用する。研究内容は題名・問い・方法を独立保存し、発見・限界は一件ずつ追加・選択・更新・削除する。短い修正で他の長文を再送せず、一覧HTMLには各項目の冒頭だけを置き、選択中の一件だけ全文を表示する。sceneでは意味のあるまとまりを選んで一括追加する入口と、一件ずつ追加する入口を分ける。どちらから作ってもcomponentの複製、削除、親子構造、並び、内容、配置、見た目、data itemはMCPの小粒度toolとWeb UIの両方から編集できる。表示stepはsame-originの固定message schemaで切り替え、iframeを再読込しない。

sceneの構成outlineは保存配列の順ではなく、親子関係と`order`から木構造として表示する。各componentには自動配置／自由配置と表示STEPを併記する。中央iframeを保存後またはSTEP切替後に再読込している間は、黒い空欄に見えないよう読み込み中のフィードバックを表示する。

読み上げsegmentは一枚編集Web UIでもSTEPごとに追加・削除でき、文言、表示話者、VOICEVOX profile、7種の調声値を修正できる。一つのsegmentは最大8個の発話ブロックへ分けられ、ブロックごとにprofile、速度、高さ、抑揚、直後の休符を設定する。発話ブロックの文章を順につないだ値をsegmentの表示文とし、表示と音声を別々には編集させない。segmentには読み上げ前と読み上げ後の余白も持たせる。追加前の原稿も対象STEPの実rendererへ表示し、ブラウザ仮試聴と休符込みの概算時間を確認する。原稿、profile、調声値、発話ブロックが変わったsegmentの`audio_src`は保存時に`null`へ戻し、古い設定から生成した音声を再利用しない。画面にはVOICEVOX標準値、profile基準値、segment上書き値から解決した実効値と、生成音声／browser fallbackの状態を表示する。

rendererは16:9または4:3のstageをsize containerとし、flow、canvas、scene、読み上げ欄の寸法をstage基準で計算する。font読込後とresize後に本文、補足、字幕、leaf componentを測定し、安全な下限まで自動fitする。それでも残るoverflowは編集frameから親画面へ対象付きで通知し、品質確認欄へ表示する。公開画面には編集用警告を出さない。表紙前の0ページ目は画像・生成音声・fontを事前読込し、開始クリック後に実経過時間と初回読み上げを始める。0ページ目はslide数、発表進捗、想定時間には含めない。

### スライドレビューWeb UI

編集inspectorへコメント機能を重ねず、研究詳細と一枚編集画面から専用レビュー画面へ移動する。左に未解決コメント数付きfilmstrip、中央に公開版と同じ実renderer、その下に一枚分の保存テキスト、右にコメント作成・一覧・AI修正依頼文を置く。画面テキストと音声原稿は同じ平坦な一覧へ置き、色、ラベル、`target_kind`で区別する。flowの本文・補足・段階表示、canvas block、scene componentとdata item、代替テキスト、音声segmentを安定した`target_key`へ対応付ける。1列表示では文章の範囲を選んだ直後にコメント入力欄へ案内し、範囲指定を解除したときは過去の成功・警告表示も消して現在状態と一致させる。

範囲コメントは現在本文に対するUTF-16の開始・終了位置、選択文、前後80文字の文脈をD1へ独立保存する。作成APIは現在の研究を再取得し、位置の部分文字列と選択文が一致する場合だけ受理する。研究documentとコメントのversionは別にし、コメント追加・解決・削除では研究versionや固定previewを古くしない。表示時は次の順でアンカーを解決する。

- 保存位置と選択文が一致：`current`
- 選択文が現在の対象内に一度だけ現れる：`moved`
- 対象が消えた、選択文がない、または複数箇所にある：`stale`

`stale`は推測で修正せず利用者へ再指定を求める。未解決コメントは`research://projects/{id}/review-comments`と20件単位のpage resourceからAI Agentも読めるようにする。Web UIで選んだ最大20件から生成するものは任意コードではなく、現在version、対象resource、アンカー状態、既存の小粒度toolだけを使う制約を含む「AI修正依頼文」とする。AIはコメントを自動で解決済みにせず、利用者が実表示を確認してからWeb UIで解決する。研究ごとのコメントは200件を上限とし、所有者条件、CSRF、入力長制限、監査イベントを適用する。

## 進行位置とURL

現在位置は `?slide=<1始まり>&step=<0始まり>` としてURLへ保存する。手動送りと自動送りのどちらも `history.pushState` で履歴へ追加し、ブラウザの戻る／進むでは `popstate` から表示位置を復元する。範囲外の値は存在する最後のスライド・段階へ補正する。URLが進捗の正本であり、進行位置は `localStorage` へ重複保存しない。レイアウトは同じURLの `layout` へ保存する。

## 音声の確認と生成

一枚編集と音声仕上げ画面ではブラウザ標準読み上げで原稿・話速・高さ・音量・休符を仮確認できる。実際のVOICEVOX試聴と固定preview用MP3は、Web UIまたはMCPからQueueへ差分jobを登録し、Cloudflare Containerの固定VOICEVOX ENGINEとffmpegで生成する。文中に複数の発話ブロックがある場合はブロックごとに合成し、指定した無音を挟んで一つのMP3へ結合する。生成中も画面を閉じてよく、Web UIとMCP resourceから状態を再取得できる。

VOICEVOXを設定した研究は、固定previewを作る前に全区間のMP3生成を必要とする。設定した話者と異なるブラウザ音声を誤って固定しないためである。VOICEVOX未設定の研究はブラウザ音声で固定previewを作れる。

## 読み上げ原稿と画面表示

読み上げ原稿は音声専用データにせず、必ず視聴者が文字でも読めるようにする。表示文と合成音声の原稿は `narration.segments[].text` を単一の情報源とする。

段階表示の `at` ごとに原稿を分割し、クリック後に表示されている内容と読み上げ対象を一致させる。

- `dialogue`：ADV風の会話枠。内容領域と重ならないよう、下部に専用スペースを確保する。
- `commentary`：ゆっくり実況等を想定した大きな字幕。短くテンポのよい文にする。
- `inline`：固定高の全文欄に原稿を配置し、現在の段落へ追従する。
- `subtitle`：映像字幕風のコンパクトな下字幕。
- `minimal`：主画面を隠しにくい最小限の字幕。

rendererは上記の値を見た目にも反映し、話者nameplate、配置、寸法、文字揃え、話者表示、進捗表示、文字倍率、最大行数を検証済みtokenから設定する。表示はrenderer既定、deck既定、slide設定の順に解決する。どの方式でも「ナレーション」のような固定ラベルを発表枠内へ追加せず、字幕本文そのものを表示する。

音声ファイルをVOICEVOX等で生成する場合も、segmentごとにファイルを分ける。スライドや段階を戻ったときは再生中の音声を停止し、現在の原稿だけを再生する。

読み上げ音量は0〜100%で調整し、`ultimate-freestyle:narration-volume` をキーとして `localStorage` に保存する。音声ファイルには再生中にも適用し、Web Speech APIの読み上げには次のsegmentから適用する。保存が利用できない環境でも、開いている間の音量変更は有効にする。

ページまたは段階を進めたときは、対応するsegmentを自動再生する。読み上げ前、発話ブロック間、読み上げ後の休符も同じ進行状態として扱い、下部の状態表示とインジケーターで待機中であることを示す。個別の再読み上げボタンは持たず、聞き直す場合は一度前へ戻ってから再度進む。自動送りを有効にした場合は`pause_after_ms`を待ってから次へ進み、音声がない段階では短い待機時間を使う。タブが非表示になった場合は音声と休符の残り時間を止め、復帰確認後に再開する。

一括生成は `bun run voicevox:generate -- <slug>` を使う。既定の出力は
`public/.voicevox-preview/researches/<slug>/audio/<slide-id>-<at>.mp3` で、
モノラル64kbpsとする。プレビュー領域、ENGINE、音声モデルはリポジトリへ含めない。
ローカル確認は `bun run dev:voicevox` を使い、通常の `bun run dev` は常にブラウザ音声を使う。

VOICEVOXはdeckの`voicevox.profiles`へ最大16個のtalk profileを定義する。参照の正本は`speaker_uuid + style_id`とし、話者名・style名は表示用snapshotとして扱う。deck既定profileに加え、segmentの`voice_profile_id`と`voice_tuning`を基準にし、`voice_cues`の各要素でprofile、話速、音高、抑揚をさらに上書きする。`pause_before_ms`、cueの`pause_after_ms`、segmentの`pause_after_ms`は100ms単位・最大10秒とする。使用したすべてのprofileからVOICEVOXクレジットを自動表示する。

生成manifestはv2とし、原稿、UUID、style ID、全調声値、ENGINE build／version、core version、話者version、catalog、ユーザー辞書、codec設定をfingerprintへ含める。`audio_src`は正本ではなく、このfingerprintから再生成できるcacheとする。

Queue messageはjob作成時のfingerprintとversionを持つ。原稿や設定が変わった古いmessageは現在の研究へ適用せず、同じfingerprintの生成済みMP3はprivate R2 cacheから再利用する。固定preview作成時は使用するMP3をrevision専用objectへ複製する。

## 音声ファイルの保管

- 生成途中のWAVはffmpeg変換用の一時ファイルであり、処理後に削除する。
- ローカル確認用MP3、ENGINE、音声モデルはGitへ含めない。
- 生成MP3はfingerprint単位のprivate R2 cache、確認・公開用はrevision専用R2 objectへ保存する。
- 音声ファイルはGitとGit LFSへ保存しない。
- 音声の正本は原稿、話者・話速等の設定、ENGINEバージョンであり、キャッシュ失効時にも再生成可能な状態を維持する。
