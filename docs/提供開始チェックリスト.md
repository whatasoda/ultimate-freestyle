# 提供開始チェックリスト

限定提供を開始する前と、障害時に運営者が確認する正本です。技術構成の正本は `docs/remote-mcp-plan.html`、利用者向けの説明は本番 `/guide` と `/data` です。

## 開始判定

次をすべて満たした時だけ、招待を送ります。

- [x] Twitch OAuth、PKCE、CSRF、所有者分離、公開前の本人確認が自動テストで固定されている
- [x] MCP、OAuth protocol、Web書き込みに本文上限とrate limitがある
- [x] 研究単位とアカウント単位の全削除があり、R2削除失敗はoutboxから再試行される
- [x] 監査記録は180日、VOICEVOX試聴cacheは30日で整理される
- [x] 依存脆弱性監査、contract test、migration、deploy、本番smokeがmain pushの直列gateになっている
- [x] KVの保守モードで新規認証、MCP、Web書き込み、音声jobの新規dispatchを即時停止できる
- [ ] Cloudflareの利用料金通知、Worker error、Queue backlog／DLQの通知先を設定した
- [ ] 本番で資格あり・資格なしのTwitchアカウントを各1件確認した
- [x] Codexの新規接続から研究作成までを、保存済み認証に頼らない状態で完走した
- [ ] ChatGPTを提供対象として案内する場合は、招待者と同等のplan／workspaceでOAuthとtool呼び出しを完走した
- [x] 本番でVOICEVOX生成を1job完走し、固定previewと公開版へ音声をsnapshotできた
- [ ] 限定提供の案内に、運営者への連絡手段、対象者、試用期間、障害時の告知場所を記載した

未完了のクライアントは「対応済み」と案内しません。たとえばChatGPT実機確認前なら、Codexを正式経路、ChatGPTを検証中として開始できます。

2026年8月1日の本番確認では、398文字・15区間のVOICEVOX jobが193.8秒で完了し、失敗区間は0、生成MP3は15件・598,563 bytesでした。公開revisionにも音声snapshotがあります。話者クレジットの目視だけは招待前の公開画面確認に含めます。

## リリース前の機械検証

リポジトリ直下で次を実行します。

```sh
bun install --frozen-lockfile
bun run launch-check:mcp
```

`launch-check:mcp` は依存監査、型・schema・contract・coverage・dry-run build、本番smokeを実行します。mainへpushした場合もGitHub Actionsが同じ検証後にD1 migration、Worker／Container deploy、本番smokeを直列実行します。

Cloudflareの状態は `apps/mcp-server` で次を確認します。

```sh
bunx wrangler d1 migrations list ultimate-freestyle --remote --config wrangler.jsonc
bunx wrangler d1 time-travel info ultimate-freestyle --config wrangler.jsonc
bunx wrangler queues info ultimate-freestyle-voice-jobs --config wrangler.jsonc
bunx wrangler queues info ultimate-freestyle-voice-jobs-dlq --config wrangler.jsonc
bunx wrangler r2 bucket lifecycle list ultimate-freestyle-media --config wrangler.jsonc
```

R2には `voice-sample-cache-30d` があり、prefix `voice-samples/` を30日で失効させます。研究・preview・公開版のobjectへ期限規則を設定しません。

## 緊急停止と再開

認証異常、権限分離の疑い、急な費用上昇があれば、`apps/mcp-server` で保守モードを有効にします。

```sh
bunx wrangler kv key put ops:service_mode maintenance --binding AUTH_STATE_KV --remote --config wrangler.jsonc
curl -fsS https://saijiyu-kenkyu.2764.moe/healthz
```

`healthz` の `mode` が `maintenance` なら、新規認証、MCP、Web書き込み、音声jobの新規dispatchを503で停止しています。公開済み発表と案内ページは閲覧を継続し、削除outboxと期限切れデータの整理は継続します。Queueへ投入済みの音声jobは最大1件ずつ処理されるため、完全停止が必要ならCloudflare DashboardでQueue consumerも停止します。

原因を解消し、本番smokeを通した後に再開します。

```sh
bunx wrangler kv key delete ops:service_mode --binding AUTH_STATE_KV --remote --config wrangler.jsonc
bun run smoke
```

## 日次・週次の運用

日次はCloudflare Workers Logsで `INTERNAL_ERROR`、`OAuth request failed`、`VOICEVOX queue message failed`、`R2 deletion outbox` を確認し、DLQ件数と料金通知を確認します。token、cookie、研究本文をログや問い合わせへ貼りません。

週次は次を確認します。

- voice jobの成功率、処理時間、生成文字数、出力容量
- R2、D1、KV、Queue、Containerの使用量と前週差
- `storage_deletion_outbox` の滞留件数と最古時刻
- 依存更新とGitHub Actionsの失敗
- 利用者が接続から初回保存まで運営者の介助なしで完了できたか

## 障害別の判断

| 状況 | 初動 | 再開条件 |
|---|---|---|
| 認証・所有者分離の疑い | 直ちに保守モード、該当ログのrequest IDを保存 | 原因修正、回帰テスト、本番smoke、影響範囲の確認 |
| VOICEVOX失敗増加 | 新規生成を案内上停止。急増時は保守モード | 短い本番jobが成功し、DLQとoutboxが空または説明可能 |
| Worker deploy後のsmoke失敗 | 新規招待を停止し、GitHub ActionsとWorkers Logsを確認 | 修正版deploy、またはCloudflare version履歴から明示rollback後にsmoke成功 |
| R2削除outbox滞留 | 公開・認証は継続可能。R2障害とobject key errorを確認 | 滞留が減少し、再試行errorが解消 |
| 料金の想定超過 | 保守モード。Container、Queue、画像、公開trafficの内訳を確認 | 上限または原因を確定し、通知閾値を更新 |

## 利用者データ

利用者はWeb UIから研究一件、またはTwitch識別情報とMCP grantを含むアカウント全体を削除できます。削除すると公開URLは直ちに無効になり、R2 objectはoutboxへ移って再試行されます。D1 Time Travelにはプランの保持期間だけ削除前状態が残り得るため、この点を `/data` で事前説明します。
