# 管理画面デザインシステム v1

## 決定

管理画面は「フレッシュ・ラボ 80% + 陽だまりスタジオ 20%」を基礎にする。

- 構造は明快で機能的にする。
- 温かさは背景、言葉遣い、前向きな案内に限定する。
- 配色は空色とアプリコットを軸にする。
- 本文は可読性を優先し、見出しだけ少し柔らかくする。
- デスクトップの情報密度は標準とする。
- ライト／ダークはOS設定を初期値にし、利用者の手動選択を保存する。

## UI原則

1. 一つの領域で強調する主操作は一つにする。
2. カードは独立した操作単位だけに使い、カードの入れ子を作らない。
3. 一覧、履歴、コメント、設定項目は余白と区切り線を基本にする。
4. 次に必要な操作を、ページの冒頭または作業対象の直後に示す。
5. 補助操作、危険操作、状態表示を主操作から視覚的に分離する。
6. 色だけで状態を伝えず、文言やアイコンを併用する。
7. ライト／ダークで情報構造と操作階層を変えない。
8. 一つのペインへ操作や縦スクロールを集中させない。

## 配色の役割

| 役割 | 色 | 用途 |
|---|---|---|
| Primary | 空色 | 主操作、選択、現在位置、リンク |
| Warm accent | アプリコット | 次の一歩、前向きな案内、軽い達成感 |
| Success | 青緑 | 保存済み、完了、公開準備完了 |
| Warning | 琥珀 | 注意、確認が必要な状態 |
| Danger | 赤 | 削除、失敗、回復が必要な状態 |
| Neutral | 暖かい白／濃紺チャコール | 背景と作業面 |

アプリコットを通常のボタンや装飾へ広く使わない。意味を持つ案内だけに使い、画面全体をパステル調にしない。

## 面と境界

- ページ背景と主要作業面の二層を基本にする。
- 影はモーダル、ポップオーバー、フロート操作だけに使う。
- 通常のセクション、一覧、フォーム群には影を使わない。
- 角丸は入力、ボタン、独立した操作面に限定する。
- リスト項目を一件ずつカード化しない。

## 操作階層

- Primary: 現在の文脈で最も進行に寄与する一操作。
- Secondary: 並行して行える通常操作。
- Quiet: 補助、表示切替、詳細表示。
- Danger: 削除などの不可逆操作。通常操作から距離を置く。

Primaryを同じ領域に複数置かない。保存が自動なら「保存」ボタンをPrimaryとして常駐させず、保存状態を静かに表示する。

## 代表画面

- 研究一覧: 次の一歩を冒頭へ置き、研究はカード列ではなく行で示す。
- スライド編集: フィルムストリップとプレビューを上段、編集ドックを下段に置く。右ペインへ全設定を集中させない。
- レビュー: プレビュー、フラットな文章、コメント入力、コメント一覧を中央の連続した流れにする。右側の独立スクロール領域を作らない。
