# ADR 0011: 公開URLに版指定の入口を足す

## 状態

採用（2026-09-05）

## 決定

- `/p/<slug>` は今まで通り、所有者が明示的に公開操作した版だけを映す。固定preview作成では切り替わらない。
- `/p/<slug>/r/<revision-id>` を追加し、その版を固定して配信する。
- 版指定URLで配信するのは`published_at`を持つrevisionに限る。固定previewを作っただけの版は、revision IDを知っていても外部から開けない。
- 公開停止中は`/p/<slug>`と版指定URLの両方を404にする。公開の入口は1つの状態で開閉する。
- revision素材（画像・音声）の配信条件を「現在公開中のrevision」から「公開したことのあるrevisionのうち、その研究が公開中のもの」へ広げる。
- 版指定URLに`immutable`を付けない。

## 理由

配信のたびに新しいURLを配り直すと、発表前に共有したリンクが指す先を後から直せない。一方、公開URLが常に最新を映すだけでは、当日見せた版がどれだけの内容だったかを後から示せない。2つの入口を分けると、共有済みリンクは触らずに中身を直せて、確定した版も残せる。

版指定を「公開したことのある版」に限るのは、revision IDがUUIDとはいえ、未公開の下書きが推測可能な位置に置かれる状態を作らないためである。

公開停止で版指定URLも閉じるのは、「公開を停止」が全ての外部入口を閉じる操作であることを保つためである。版指定URLだけが生き残ると、停止したつもりの内容が配信され続ける。

## 見送った案

- 版指定URLを公開状態と独立させ、一度公開した版を恒久リンクとして残す案は、公開停止が効かない経路を作るため採用しない。
- 固定preview作成で`/p/<slug>`が自動追従する案は、所有者が終了画面まで確認していない版がそのまま配信に出るため採用しない。
- 版指定URLへ`immutable`を付ける案は、内容が不変でも公開停止で到達不可になる一方、ブラウザcacheが停止後も配り続けるため採用しない。

## 制限

- 版指定URLは研究単位の公開状態に従属する。版ごとの個別公開・停止は持たない。
- revisionを削除すると、その版指定URLは復元できない。

## 検証

- 公開後に版指定URLが200を返し、公開URLと同じ内容であることをWeb E2Eで確認する。
- `published_at`を持たないrevisionを版指定URLで開けないことを、R2に実体を置いた状態で確認する。
- 公開停止後に公開URLと版指定URLの両方が404になることを確認する。
