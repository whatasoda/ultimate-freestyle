# 0008 発表比率・表紙・0ページ目を別の設定層として扱う

## 決定

- 発表比率はdeck単位の`aspect_ratio`で管理し、`16:9`と`4:3`を選べるようにする。未指定は`16:9`とする。
- 通常スライドと表紙相当のスライドは同じslides配列で管理する。表紙は`role: cover`と`cover_layout`で見た目を選び、進捗上は通常の1ページとして扱う。
- 表紙より前の準備画面はslides配列へ入れず、deckの`loading_screen`とrenderer内の0ページ目で扱う。
- 0ページ目は画像、生成音声、利用可能なfontの読み込みを集約する。失敗や10秒の待機上限に達しても開始を妨げない。
- 発表の実経過時間と最初の読み上げは、0ページ目の開始ボタンを押した時点から始める。
- templateの領域配置は従来の単一・左右補足・下段補足に、左右均等・上段補足・中央集中を追加する。
- templateの色は従来の5色に第2アクセントと境界線を追加する。任意CSSは受け付けない。

## 理由

比率、表紙、読み込み状態を一つのlayout値へ詰め込むと、URL復元、進捗、音声開始、編集範囲が曖昧になる。比率は発表全体、表紙は一枚、0ページ目は開始前の一時状態として分離することで、既存の`slide=1`以降の意味を維持できる。

開始ボタンは音声再生に必要なブラウザのユーザー操作も兼ねる。preload失敗を発表不能へ結び付けず、生成音声は再生時のWeb Speech fallbackを維持する。

## 互換性

追加fieldはすべてschema version 1のoptional fieldとし、保存済みprojectを移行しない。rendererの既定値で16:9、0ページ目有効、通常スライド、中央表紙を解決する。renderer変更後に古い固定previewを公開しないため、成果物versionを`uf-renderer@3`へ更新する。

## 検証

- schemaと小粒度MCP toolで比率、0ページ目、表紙、領域配置、追加色を検証する。
- Web UIでは発表全体と一枚の設定範囲を分けて表示する。
- 16:9と4:3のeditor frameが同じ比率で描画されることを確認する。
- 0ページ目がslide数、進捗、想定時間へ含まれず、開始後に読み上げと経過時間が始まることを確認する。
- renderer更新を含むpreviewは再生成して実寸で確認する。
